# Neural Network Integration Plan — Netting Broker Simulation

## Overview

We will add a **feedforward neural network** trained to predict the best routing
decision for each incoming order: should it be crossed internally, or sent straight
to the external market?

The network learns from thousands of synthetic broker scenarios generated by the
existing simulation engine.

---

## 1. What the Network Predicts

**Task:** Binary classification + regression (multi-output)

| Output neuron | Meaning | Type |
|---|---|---|
| `matchProb` | Probability that an internal match is available | 0–1 |
| `expectedSavings` | Predicted savings per share vs. going external | continuous |
| `routeRecommendation` | 0 = route external, 1 = cross internal | binary |

**Input features (8 neurons):**

| # | Feature | Description |
|---|---|---|
| 1 | `buyQtyNorm` | Normalized buy order size (÷ 100) |
| 2 | `sellQtyNorm` | Normalized sell order size available on book (÷ 100) |
| 3 | `spreadNorm` | Bid-ask spread (÷ 1) |
| 4 | `imbalance` | (buyQty − sellQty) / (buyQty + sellQty) |
| 5 | `midPriceNorm` | Mid price normalized (÷ 200) |
| 6 | `bookDepthBuy` | Number of buy orders in book (÷ 10) |
| 7 | `bookDepthSell` | Number of sell orders in book (÷ 10) |
| 8 | `historicalMatchRate` | Rolling internal match rate (0–1) |

---

## 2. Architecture

```
Input Layer       Hidden Layer 1    Hidden Layer 2    Output Layer
 (8 neurons)  →   (16 neurons)   →  (8 neurons)    →  (3 neurons)
                  [ReLU]            [ReLU]             [Sigmoid x3]
```

- **Activation:** ReLU for hidden layers, Sigmoid for outputs
- **Loss function:** Binary cross-entropy for classification + MSE for regression (combined)
- **Optimizer:** Mini-batch Stochastic Gradient Descent with momentum
- **Learning rate:** 0.05 with decay (÷ epoch)
- **Batch size:** 32
- **Epochs:** 200 (≈ 2–4 minutes on modern CPU)

## 3. Files to Create

### `nn_core.js` — Neural Network Engine
Runs in both Node.js and browser (pure JS, zero dependencies).

**Contents:**
- `Matrix` utility class (multiply, transpose, add, apply)
- `NeuralNetwork` class:
  - `constructor(layers)` — initialize random weights with Xavier init
  - `forward(input)` — forward pass, returns all activations
  - `backward(input, targets, lr)` — backpropagation, updates weights
  - `train(dataset, epochs, batchSize, lr, onProgress)` — full training loop
  - `predict(input)` — single prediction
  - `save()` / `load(json)` — serialize/deserialize weights to JSON

---

### `train.js` — Training Script (Node.js)
Run from terminal: `node train.js`

**What it does:**
1. Generates **50,000 synthetic broker scenarios** using randomized parameters
2. Labels each scenario (was there an internal match? what were savings?)
3. Splits into 80% train / 20% validation
4. Trains the network for **200 epochs** with mini-batch SGD
5. Prints epoch progress every 10 epochs with loss + accuracy
6. Saves results to `training_results.json`:
   - Final weights (`model_weights`)
   - Loss history per epoch
   - Accuracy history per epoch
   - Confusion matrix on validation set
   - Sample predictions

**Expected runtime:** 2–5 minutes

---

### `results.html` — Results Visualization Page
A standalone HTML page that reads `training_results.json` and shows:

1. **Loss curve** — training vs validation loss across epochs (canvas chart)
2. **Accuracy curve** — accuracy over epochs (canvas chart)
3. **Confusion matrix** — heatmap: predicted vs actual routing decisions
4. **Sample predictions table** — 20 random samples with inputs, predicted output, actual label
5. **Network architecture diagram** — animated SVG of the neural network layers
6. **Key metrics panel** — final accuracy, precision, recall, F1 score

## 4. Data Generation Strategy

Synthetic scenarios are generated with these rules (matching the MD document):

```
For each scenario:
  bid  = random(95, 105)
  ask  = bid + random(0.05, 0.20)      // realistic spread
  mid  = (bid + ask) / 2
  buyQty  = random(1, 100)
  sellQty = random(0, 100)             // 0 = no seller available
  bookDepthBuy  = random(0, 10)
  bookDepthSell = random(0, 10)
  historicalMatchRate = random(0, 1)

  // Label: can we match internally?
  canMatch = sellQty > 0 AND imbalance < 0.9
  matchedQty = min(buyQty, sellQty)
  savings = matchedQty * (ask - mid)   // buyer savings per share
```

## 7. Key Design Decisions

| Decision | Rationale |
|---|---|
| Pure JS, no libraries | Works in browser AND Node.js with same code |
| Xavier weight init | Prevents vanishing/exploding gradients on ReLU |
| Mini-batch SGD | Faster than full-batch, more stable than single-sample |
| 200 epochs | Enough to converge; ~2–5 min on CPU without GPU |
| Combined loss | Jointly optimizes both classification and regression outputs |
| Synthetic data | Allows millions of controlled training samples |

---

## 8. Expected Results

Based on the data generation logic, we expect:

- **Final validation accuracy:** ~88–93%
- **Loss convergence:** by epoch 80–120
- **Precision (internal match):** ~90%
- **Key learned pattern:** The network learns that high `sellQtyNorm` + low
  `imbalance` + high `historicalMatchRate` strongly predicts internal matching
